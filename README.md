# ניתוח שגרת טיפולים לרכב

**דשבורד חי:** https://timetrack-app-kevr.vercel.app

מערכת שקוראת מסמכי טיפולים בפורמט PDF — דו״חות ליסינג, תדפיסי יבואן וחשבוניות
מוסך — ובונה מהם תמונה אחת של שגרת הטיפולים של הרכב: מתי הטיפול הבא, האם
המרווחים נשמרים, מה מצב פריטי הבלאי, וכמה זה עולה.

**דשבורד:** אפליקציית React (`src/`) שטוענת את `public/vehicle-data.json`.
**פייפליין:** חילוץ וניתוח בפייתון (`pipeline/`) — ראו [`pipeline/README.md`](pipeline/README.md).

## עדכון הנתונים

הנתונים נבנים מחדש **אוטומטית**: כל שינוי תחת `pipeline/` שנדחף ל-`main`
מריץ את הפייפליין ומעדכן את `public/vehicle-data.json`, והדשבורד עולה מחדש.
בפועל זה אומר שהוספת קבלה, חשבונית או קריאת מד אוץ מספיקה — כל המספרים
(צריכה, עלות לק״מ, קצב נסיעה, תחזית הטיפול הבא, ההתראות) מחושבים מחדש לפי
כל מה שקיים באותו רגע.

הריצה חוזרת גם פעם בשבוע, כי חלק מהמספרים יחסיים להיום — ״בפיגור של N ימים״,
מד האוץ המשוער — ומתיישנים גם בלי שנוסף מסמך.

בדשבורד יש שני כפתורי **העלאה** — "העלאת קבלה" במקטע הדלק ו"העלאת חשבונית"
במקטע ההיסטוריה. הם פותחים את דף ההעלאה של GitHub על התיקייה הנכונה: גוררים
לשם קובץ אחד או **כמה קבצים יחד**, מקמטים בקומיט אחד, והבנייה מחדש רצה. מסמך עם שכבת טקסט נקרא אוטומטית; מסמך
סרוק ידווח כאזהרה בדשבורד עד שיתומלל.

בנוסף יש טופס להזנת תדלוק ידנית (כפתור **+ תדלוק**). הוא מציג תצוגה
מקדימה של הצריכה שתתקבל, מזהיר אם המספרים לא מסתדרים, ופותח את קובץ ה-JSON
מוכן לקומיט ב-GitHub. אין backend ואין נקודת כתיבה פומבית — גיט נשאר מקור
האמת היחיד, והקומיט מפעיל את הבנייה מחדש.

להוספת נתון:

| מה | לאן |
| --- | --- |
| טיפול / חשבונית מוסך | `pipeline/data/pdfs/` |
| קבלת דלק (PDF עם טקסט) | `pipeline/data/fuel/` |
| תדלוק או מד אוץ ידני | `pipeline/data/fuel/<תאריך>.json` — או דרך כפתור **+ תדלוק** בדשבורד |
| מסמך סרוק | `python -m vehicle_maintenance.ocr <קובץ> --kind fuel\|service` |

מקטע **מסמכי מקור** בתחתית הדשבורד מציג כל קובץ שנטען ומה קרה לו — נקרא,
תומלל, או ממתין לתמלול — כך שאחרי העלאה של כמה מסמכים אפשר לראות שכולם נקלטו
ולא רק מה שנכשל.

## הרצה

```bash
npm install && npm run dev          # דשבורד

cd pipeline
pip install -r requirements.txt
python -m vehicle_maintenance.build # בניית הנתונים מחדש מה-PDF-ים
python -m pytest tests/ -q
```

## מה המערכת מחשבת

- **מרווחים בין טיפולים** בק״מ ובימים, מול תוכנית היצרן (15,000 ק״מ / 12 חודשים).
- **קצב נסיעה נוכחי** לעומת ממוצע כל התקופה, והערכת מד האוץ להיום.
- **תחזית לטיפול הבא** — תאריך, מד אוץ, וכמה זמן נשאר.
- **פריטי בלאי** (רצועת תזמון, בלמים, צמיגים) — מתי טופלו לאחרונה וכמה נשאר למרווח.
- **עלויות** — לכל ביקור, לק״מ, ולפי מערכת.
- **דלק** — צריכה ועלות חודשית/שנתית, ופילוח עלות אחזקה כוללת (דלק מול טיפולים).
  נמדד מרישומי תדלוק ב-`pipeline/data/fuel/` כשיש, ואחרת אומדן מסומן ככזה.
  קריאות מד האוץ שברישומי התדלוק מזינות גם את קצב הנסיעה ואת תחזית הטיפול.
- **התראות** על פיגור, חריגה מהתוכנית, ותיעוד חסר.

הפורמטים הנתמכים כרגע הם דו״ח ״תעודת זהות לרכב״ של אלדן ותדפיס ״הסטורית רכב״
של היבואן. חשבוניות סרוקות (ללא שכבת טקסט) נכנסות דרך `pipeline/data/manual/`.
פורמט חדש = פרסר חדש ב-`pipeline/vehicle_maintenance/parsers/`.
