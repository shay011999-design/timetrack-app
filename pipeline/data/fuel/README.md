# רישומי תדלוק

כל קובץ JSON כאן הוא תדלוק אחד. ברגע שיש שני תדלוקי מכל-מלא רצופים, המערכת
מודדת את **הצריכה בפועל** במקום להשתמש באומדן שב-`data/config.json`.

```json
{
  "date": "2026-09-01",
  "odometer": 160120,
  "litres": 42.3,
  "price_per_litre": 8.25,
  "total": 348.98,
  "station": "פז אשדוד",
  "full_tank": true,
  "km_since_last_fill": 329,
  "computer_l_per_100km": 13.4
}
```

- `full_tank` — האם מילאת מכל מלא. תדלוק חלקי נרשם ונספר בהוצאה, אבל לא סוגר
  חלון מדידת צריכה, כי לא ידוע כמה דלק היה במכל.
- מספיק למלא `litres` + `price_per_litre` **או** `litres` + `total`; מה שחסר מחושב.
- `odometer` — קריאת מד האוץ. חשובה גם מעבר לדלק: היא מזינה את קצב הנסיעה ואת
  תחזית הטיפול הבא, ובדרך כלל היא הקריאה העדכנית ביותר שיש במערכת.
- `km_since_last_fill` — המרחק מאז התדלוק הקודם, ממסך "Since refuelling" במחשב
  הדרך. **זה מה שמאפשר לתדלוק בודד למדוד צריכה.** בלעדיו צריך שני תדלוקי מכל-מלא.
- `price_per_litre` — אם לא מוזן, נגזר מטבלת המחירים ב-`config.json` לפי התאריך.
- `computer_l_per_100km` — הצריכה שהמחשב עצמו מדווח. לא משמשת לחישוב, רק להשוואה
  מול מה שהמשאבה באמת נתנה.

שיטת המדידה היא tank-to-tank: המרחק שנסע על מכל אחד, חלקי הליטרים שמילאו אותו
בחזרה — הדלק שנכנס הוא בדיוק מה שנצרך במרחק הזה. המרחק נלקח מהפרש מד האוץ בין
שני תדלוקים, ואם אין כזה — מ-`km_since_last_fill`. כששניהם קיימים מד האוץ מנצח,
כי מחשב דרך אפשר לאפס באמצע מכל.

מיכל אחד הוא נקודת מדידה, לא הרגל. עד שלושה מיכלים המספר מסומן כארעי.
